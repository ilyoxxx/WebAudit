WebAudit GitHub

Documentation API

Lance des audits depuis tes scripts, ta CI ou ton application.

Démarrage rapide

  1. Va sur la page d'accueil et connecte-toi avec GitHub.
  2. Crée une clé API. Elle n'est affichée qu'une seule fois : copie-la tout de suite.
  3. Envoie-la dans l'en-tête x-api-key de chaque requête.
curl -X POST ORIGIN/api/scan \
  -H "Content-Type: application/json" \
  -H "x-api-key: wa_votre_cle" \
  -d '{"url":"exemple.fr"}'

Lancer un audit

POST /api/scan

ÉlémentDétail
En-tête Content-Typeapplication/json
En-tête x-api-keyTa clé API. Facultatif : sans clé, la limite gratuite s'applique.
Corps urlL'adresse à analyser, avec ou sans https://.

Exemple en JavaScript

const res = await fetch('ORIGIN/api/scan', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-api-key': process.env.WEBAUDIT_KEY,
  },
  body: JSON.stringify({ url: 'exemple.fr' }),
});
const report = await res.json();
console.log(report.grade, report.score);

Les champs exacts peuvent légèrement varier selon les règles. Les textes lisibles correspondent aux clés de /locales/fr.json.

Statuts d'une règle

StatutSignification
passLa vérification est réussie.
warnPoint à améliorer, sans être bloquant.
failProblème détecté : voir remediationKey pour la correction.
naNon applicable, ou analyse non concluante (site bloqué ou chargé en JavaScript). Ce n'est pas un échec : vérifie manuellement.

Limites

  • Sans clé : 3 scans par jour et par adresse IP.
  • Avec une clé : la limite quotidienne gratuite ne s'applique pas.
  • Clés : 3 maximum par compte GitHub. Supprime-en une pour en recréer une.
  • Un scan peut durer plusieurs secondes : prévois un délai d'attente d'au moins 60 secondes côté client.

Codes d'erreur

CodeErreurCause
400Missing "url"Le champ url est absent ou n'est pas du texte.
401invalid_api_keyLa clé est inconnue ou a été supprimée.
429free_limit_reachedLimite de 3 scans gratuits par jour atteinte. Utilise une clé API.
502scan_failedLe site cible n'a pas pu être analysé (inaccessible, expiré, etc.).

Lister les règles

GET /api/rules renvoie l'identifiant, la catégorie, le poids et le lien de documentation de chaque règle.

Sécurité de ta clé

  • Ne la mets jamais dans du code public ni dans un dépôt Git. Utilise une variable d'environnement.
  • Nous ne gardons qu'une empreinte de ta clé : si tu la perds, supprime-la et crée-en une nouvelle.
  • Une clé qui a fuité doit être supprimée immédiatement depuis la page d'accueil.

Contribuer

WebAudit est open source. Les règles vivent dans /src/rules : lis le guide de contribution.
